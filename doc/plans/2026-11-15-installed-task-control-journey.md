# Installed deterministic task and recovery qualification

Extend the same installed Windows/macOS browser-onboarding journey with a hired
process worker reporting to the deferred setup agent. Run the installed Electron
executable in embedded-Node mode, not a developer Node installation. This is an
explicit deterministic CI provider, never an AI-model qualification.

The worker reads an unpredictable owned input file, creates a file, registers an
authenticated issue attachment and work product, and emits bound run/issue/asset
receipts. The board reads back identical bytes. Separate actual child runs are
cancelled and timed out; their recorded PIDs must stop. Opaque process outcomes
remain held before replay. The board truthfully reconciles the instrumented hold
branch's not_performed outcome, then repeats the same durable Retry intent.
Verify the exact task/source lineage through authorized run details and one
effective continuation, whether Retry or reconciliation owns delivery.

After closing and reopening the actual app, verify original-session access,
all four run outcomes, task completion, attachment bytes and work-product links.
Existing PostgreSQL shutdown, uninstall and data-preservation checks remain.
No native deadlines are increased. Artifact operations use30s because the fixture
permits two sequential10s requests plus startup; hold timeout/cancellation still
use15s, and recorded policies are asserted. No control or replay bypass is added.

An actual source HTTP/process/storage/recovery/restart journey at67d8ab9e passed
15/15 checks under Electron45.2.3/Node24.22.2, and the exact owned PostgreSQL
cluster subsequently reported stopped. This was not browser/installed/model
execution. It required the production Windows cwd fixes in separate PR566.
The native candidate must include those qualified fixes before this extension
can establish installed acceptance. Native qualification remains pending.

Earlier source failures remain retained: incorrect lifecycle/summary assumptions,
an inconsistent initial artifact fixture budget, startup resource pressure, and
real deep-Windows child creation crashes. Run lists intentionally omit private
lineage; the helper now uses full authorized details. Genuine source crashes
were fixed in their owning preparation/readiness services, not swallowed here.

The provider refuses non-local API origins, requires its explicit CI flag and
run identity, keeps credentials off stdout/stderr, and atomically publishes an
exclusive complete PID receipt. Actual embedded-Node controlled-server tests
verify authenticated request/byte bindings and duplicate-run refusal. Fixture
workspace and data remain within the native wrappers' existing owned cleanup.
