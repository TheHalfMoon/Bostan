# B1-235 — Pin installed pnpm 9.15.4 and avoid shell shims in local PostgreSQL QA

Date: 2026-11-07 Asia/Riyadh. **PRIVATE / DRAFT / UNMERGED / RELEASE NO-GO.**

## Real executable provenance gap

B1-234 correctly pinned six PostgreSQL CLI executables to an explicit trusted bin directory, but its test-only migration runner still called bare `pnpm` via `PATH` on POSIX and relied on `process.env.ComSpec || 'cmd.exe'` with `pnpm.cmd` on Windows. This reintroduced operator PATH and shell-shim ambiguity during three actual migration invocations. It also allowed Corepack to locate or try to fetch a package manager, conflicting with the deliberately offline private QA profile. The root `package.json` already pins **`pnpm@9.15.4`**.

## Implemented

- New standalone `scripts/bostan-local-pnpm-entry.mjs` requires an **explicit preinstalled physical** package directory `BOSTAN_PNPM_PACKAGE_DIR`. It accepts only `package.json` with `name=pnpm`, `version=9.15.4`, and `bin.pnpm=bin/pnpm.cjs` (optionally `./bin/pnpm.cjs`). It refuses absent, linked or hardlinked files, linked package directory, missing CLI, inconsistent version, and group/world-writable POSIX package/bin/entry files. Windows path must be directly rooted on a local drive, not UNC.
- The helper captures the package directory and CLI/manifest dev/inode/birthtime identities **and SHA-256 digests of manifest and JS entry**; it rechecks the same identities/digests before each migration invocation. This detects even in-place content mutation with no path or inode change. Failures return a bounded, path-free message.
- Real `scripts/bostan-local-postgres-migration-qualification.mjs` now verifies the repository root `packageManager=pnpm@9.15.4`, captures the trusted pnpm entry **before creating scratch**, and invokes it as `process.execPath` with absolute `pnpm.cjs` as first argument. Thus all three migrations run without `cmd.exe`, `pnpm.cmd`, bare PATH `pnpm`, or a Corepack download shim. `qaExec` refuses arbitrary tool names.
- **Existing B1-234 physical PostgreSQL tool pinning, B1-233 isolated environment default, B1-232 owned private home/cleanup, B1-230 bounded diagnostic tool labels and all three migration result assertions remain in place.** `pnpm` still receives the synthetic localhost database URL and the private QA home, not operator credentials.
- Updated the existing `scripts/bostan-local-postgres-toolchain-integration.test.mjs` to provide the new pinned pnpm and host-Node test dependencies, and added `scripts/bostan-local-pnpm-entry-integration.test.mjs` for real runner source-order and VM tests.

## Strict limitations

The supplied pnpm package directory and its original contents must be trusted; this check verifies package metadata, local file identity and subsequent modifications but **not a signed publisher identity or an externally trusted artifact hash**. In-place file replacement *after* recheck and *before* Node opens the file is still a race; content in pnpm's other internal modules or workspace scripts is not hashed or confined. An installed package may use symlinks/hardlinks that this deliberately strict test refuses; select a safe real physical, owner-controlled pnpm 9.15.4 package directory before native QA. `COREPACK_ENABLE_NETWORK=0` is a safety guard but **not network egress confinement**.
